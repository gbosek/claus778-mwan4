## Source-level review notes

- Rust netlink: route message attributes, table and metric scoping, explicit protocol marks, nexthop lifecycle, link monitor and conntrack matching were traced. The policy sweep defect was found in `src/netlink/route.rs`.
- Rust state and probes: `src/main.rs`, `src/config.rs`, `src/prober.rs`, `src/lqe.rs`, `src/netlink/link.rs` were inspected; reset conditions/timeout and IPv4/IPv6 coupling require runtime cases.
- Package and LuCI: source `Makefile`, generated APK/IPK scripts, ACL permissions, `overview.js`, localization and route defaults were reviewed. Old installed configuration must not be blindly migrated from the different mossdef backend.
- Security: do not accept random offline tarballs. Only deploy builds produced from trusted reviewed commits; no unconditional claims of NPU offload.

## Required pass gates before merge

1. GitHub CI: `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`, Python compile, JS `node --check`, and POSIX shell mock tests.
2. Privileged isolated Linux kernel test: native IPv4/IPv6 ECMP, same-priority fib policy sweep, marked PBR before native from/to policies, route recovery, cleanup.
3. OpenWrt/ImmortalWrt VM with DHCP/PPPoE interface churn; verify netifd logical-to-L3 mapping, Gateway6, PBR startup/down/up ordering; assert no stale default route.
4. Hardware test: confirm actual acceleration separately using conntrack `[HW_OFFLOAD]`, driver PPE/NPU counters, WAN throughput and CPU, and IPv4 vs IPv6.
5. Packaging: packages must ship disabled with zero WANs, preserve user config, never silently replace a running default route, and be installable via standard feed.
