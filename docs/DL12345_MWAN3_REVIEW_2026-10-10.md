## 与当前 Rust MWAN4 的区别

| 设计 | dl12345 mwan3 | 我们目前的实现 / 决定 |
|---|---|---|
| nft 所有权 | 独立 `inet mwan3` 表，hook -149 | PBR consumer 的 goto 目标在 `inet fw4`，用规则文件重建；goto 不能跨表，不能直接搬走目标链 |
| mark 位 | 默认 `0x3f00`；按自有掩码保存/恢复 conntrack mark | 适配器也是 `0x3f00`，设置 meta mark 时保留其他位；本次增加活动 mwan3 冲突检查 |
| 重载 | 用单个 nft 批次重建，同时保留用户 set | 适配器 NFT 批次已有原子性和幂等性；MWAN4 服务重载仍会停启守护进程，不能宣称整体无间断 |
| 分配与 sticky | numgen 按权重选 WAN，ct mark 保持已有连接；源地址 sticky 另有超时 set | 内核 ECMP 哈希 / resilient 桶；不等同于按客户端保持同一公网出口，目前没有客户端 sticky |
| 故障恢复 | 清理故障成员 sticky；优先层恢复后新连接回到较优层 | metric 分层及 WAN_prefer 健康回退已实现；已有 NAT 会话不保证无损迁移 |
| WAN 源地址回程 | 为 WAN 全局 IPv4 地址加 source rule，处理 WireGuard 的非默认 WAN 握手回复 | 探针有独立表与接口绑定，但未为全部 WAN 地址自动创建通用回程规则；有入站服务时需专门验证 |
| 严格策略 | last_resort 支持 unreachable / blackhole / default | 目前 prefer 允许回退、balanced 用全局路由；不适合作为 VPN 防泄漏策略 |
| 清理与诊断 | stop 同时核对规则优先级和内容；诊断会统一替换公网地址 | 自有 protocol 77 + 保留范围清理已实现；实机日志仍需手工脱敏，尚无完整一键脱敏诊断工具 |

## 本次实际修改

- 新增 `mwan4-pbr-compat check-mark-owner` 只读检查。
- 策略模式生成配置前调用检查，发现活动 mwan3 表或运行服务即拒绝启动。
- `check/status` 同样报告冲突；不删除其他服务的状态，不自动停服务。
- 修正 rc.common 包装层覆盖启动回调失败状态的问题；reload 也会在发布
  manifest 后调用成功钩子重载已启用 PBR，失败时跳过此钩子。
- QEMU 回归新增竞争表场景：检查与启动都失败，竞争表仍在；移除测试表后
  正常启动，继续原有策略、断线回退、重载及停止清理测试。
- 包升级为 core/LuCI r17、adapter 0.2.1，避免同版本安装遗漏更新。

## 后续改进优先顺序

1. 在 XG2010G 核对非默认 WAN 上的入站服务、WireGuard 握手回复、DHCP/PPPoE
   重拨后的源地址，再设计带路由所有权和策略优先级约束的回程规则。
2. 评估显式 strict/last_resort 目标：需要断路语义、停止服务行为和失败测试，
   不能把现有 prefer 改名当成 strict。
3. 客户端 sticky 与已有连接保持需要分别设计；确定 PPE/offload 对 mark 和
   conntrack 的实际行为后，再实现受控的旧会话清理。
4. 完善统一诊断和脱敏，覆盖路由、NFT、健康状态及日志中的地址对应关系。

这个分支在 start 的软件 flow offload 场景中仍可能清空全表 conntrack；其
原子重载后也会清理 mwan3 标记的会话。我们保留健康 WAN/PPE 流表的目标，
采用故障 WAN 的 IPv4/NAT 会话定向清理，不能照搬全表 flush，也不能把
“NFT 提交原子”描述为“已有 TCP 会话无损”。IPv6 独立探测/源前缀选择仍需
后续实现；当前只有电信 IPv6 的测试条件不改变。
